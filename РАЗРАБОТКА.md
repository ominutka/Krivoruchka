# Криворучка — устройство проекта

Документ для того, кто будет менять код. Про запуск и игру — в
[README.md](README.md) и [ПРАВИЛА.md](ПРАВИЛА.md).

---

## Три файла

| Файл | Строк | За что отвечает |
|---|---|---|
| `server.js` | ~530 | комнаты, этапы партии, режимы, движение карандаша, рассылка |
| `public/index.html` | ~840 | вся клиентская часть: вход, лобби, холст, кнопки |
| `public/roles.js` | ~100 | таблица ролей: кому какие кнопки при каком составе |

Зависимостей нет — только стандартная библиотека Node. Сборки нет:
файлы отдаются как есть. Правка `public/*` подхватывается обновлением
страницы, правка `server.js` требует перезапуска.

---

## Ключевое решение: карандаш живёт на сервере

Положение карандаша, толщина, цвет, состояние зажатых кнопок — всё
хранится и считается на сервере, тридцать раз в секунду. Клиенты не
вычисляют ничего: они получают готовые отрезки и рисуют их у себя.

Так сделано по двум причинам. Во-первых, у всех гарантированно
одинаковый холст — нет ведущего, чей браузер «главнее». Во-вторых, по
сети летят координаты, а не картинка: десятки байт вместо десятков
килобайт на кадр.

Побочное следствие: клиент почти не содержит игровой логики, и почти
любое изменение правил делается в `server.js`.

## Как устроен обмен

Сервер → клиенту идёт поток событий (**SSE**, `GET /stream`).
Клиент → серверу — обычные POST-запросы (`POST /msg`).

Асимметрия намеренная: от сервера данные идут постоянно, от клиента —
редкими всплесками при нажатиях.

### Запросы

| Адрес | Что делает |
|---|---|
| `GET /new` | создаёт комнату, возвращает `{room: "ABCD"}` |
| `GET /roster?room=CODE` | состояние комнаты или `{error:"no-room"}` |
| `GET /stream?cid=…&room=CODE` | поток событий, живёт всё время игры |
| `POST /msg` | действие игрока; в теле обязательны `cid` и `room` |

`cid` — идентификатор устройства. Клиент генерирует его один раз и
держит в `sessionStorage`, поэтому перезагрузка страницы не отбирает
роль.

### События сервера

| Тип | Когда | Содержит |
|---|---|---|
| `hello` | при подключении | размеры холста, палитра, описания режимов |
| `snapshot` | при подключении | все операции текущего раунда — догнать опоздавшего |
| `roster` | при любом изменении состава | занятые роли, ведущий, этап |
| `you` | при любом изменении | персонально: роль, ведущий ли, следующий ли в очереди |
| `round` | при изменении раунда | **персонально**: слово может отличаться (см. режимы) |
| `t` | 30 раз в секунду | положение карандаша, остаток секунд, отрезок, если рисовали |
| `seg` `blob` `stamp` | по событию | операции вне тика |
| `clear` | новый раунд | очистить холст |
| `noise` | помеха | вид и текст |
| `result` | конец раунда | загаданное слово и разоблачение |
| `shuffled` | перемешивание ролей | сигнал сбросить нажатия |
| `no-room` | комнаты нет | клиент возвращается на экран входа |

### Сообщения клиента

`input` (нажатие), `pickRole`, `claim` (забрать ведение) — доступны
всем. `mode`, `count`, `back`, `start`, `stop`, `again`, `remode`,
`clear`, `shuffle` — **только ведущему**, проверка на сервере.

## Комнаты

`rooms: Map(код → комната)`. Комната — самодостаточный объект: свои
клиенты, роли, порядок подключения, таймер и всё состояние партии `G`.
Ни одна функция не обращается к глобальному состоянию игры, все
принимают `room` первым аргументом.

Коды — четыре латинских согласных: не складываются в слова, набираются
на любой раскладке, не портят ссылку.

Пустая комната удаляется через 20 минут (`ROOM_TTL_MS`), проверка раз
в минуту.

**Ведущий** — первый в `joinOrder`. Забрать ведение может только второй
(`claimLead`), при этом бывший ведущий уходит в конец очереди — иначе
двое отбирали бы его друг у друга по кругу.

---

## Этапы партии

```
mode → count → lobby → round → result
                 ↑                 │
                 └─────────────────┘
```

`G.stage` хранит текущий этап, клиент по нему решает, какой экран
показать. Переходы делает только ведущий. Возврат к `mode` сбрасывает
роли: состав всё равно будет выбираться заново.

Роли раздаются при входе в `lobby`, по порядку подключения. Кто
подключился сверх состава — наблюдает и получает роль автоматически,
как только место освободится.

---

## Режимы

Режим меняет ровно три вещи, всё остальное общее:

1. **кто какое слово видит** — функция `taskFor(room, cid)`;
2. **бывают ли помехи** — проверка `G.mode === 'noise'` в `tick`;
3. **что вскрывается в конце** — объект `reveal` в `endRound`.

Поэтому сообщение `round` собирается **персонально для каждого
клиента** (`roundFor`): в режиме «Крот» одному уходит другое слово,
в «Проводнике» остальным уходит `null`.

Добавить режим — это дописать запись в `MODES` и учесть её в этих трёх
местах. Клиент подстроится сам: он рисует список режимов из того, что
пришло в `hello`.

## Роли и кнопки

`public/roles.js` — единственный источник правды о том, кто чем
управляет. Структура:

```js
B = { right: {a:'right', g:'→', t:'Вправо'}, ... }   // описания кнопок
ROLESETS = { 2:[...], 3:[...], ..., 6:[...] }        // наборы по составу
```

У кнопки: `a` — действие (уходит на сервер), `g` — значок, `t` —
подпись, `h` — подсказка, `tap: true` — нажатие вместо удержания,
`c` — ключ счётчика в `LIMITS`, `swatch` — рисовать кружок цвета.

`KR.roles(n)` возвращает готовые роли с цветами и подписями,
`KR.ownerOf(n)` — карту «действие → роль».

Файл общий: его читает и клиент, и тесты. Менять составы можно
свободно, остальной код только читает эту таблицу.

**Два принципа, по которым собраны наборы.** Движение всегда делится по
диагоналям. И ни одно действие не должно быть самодостаточным: клякса
была убрана из ролей именно потому, что работала в одиночку, — её место
занял «Зеркало», которое требует, чтобы кто-то другой одновременно вёл
карандаш.

## Клиент

Один файл, без сборки и фреймворков. Внутри примерно такие блоки:

- **вход** — создание комнаты и вход по коду, чтение `?r=` из адреса;
- **экраны настройки** (`renderSetup` и три функции под этапы);
- **холст** — два наложенных `canvas`: нижний накапливает рисунок,
  верхний перерисовывается каждый кадр под курсор и ось зеркала;
- **кнопки роли** (`buildPad`) — строятся из `roles.js`;
- **клавиатура** — таблица `KEYS`, работает только для действий своей
  роли;
- **приём событий** — один `switch` в конце файла.

Холст всегда 1800×1000 внутри, а на экране масштабируется по ширине
колонки. `fitStage` следит за размерами через `ResizeObserver` —
без него при наполнении правой панели холст оставался прежним и наезжал
на кнопки.

Раскладка переключается медиазапросом: узкий экран — холст сверху,
кнопки под ним; широкий — холст слева, управление и панель игроков
справа.

## Клиент отдельно от сервера

`public/config.js` задаёт `window.KR_SERVER`. Пусто — клиент обращается
туда же, откуда открыт (обычный запуск). Задан адрес — все запросы идут
на него по абсолютному пути, а клиент переключается в «встроенный»
режим: адрес страницы не меняется, ссылку с кодом передать нельзя,
поэтому вместо неё показывается сам код.

Сервер отдаёт `Access-Control-Allow-Origin: *` — секретов у него нет,
а клиент может жить на любом домене.

`build-itch.js` собирает из этого архив на три файла для itch.io,
подставляя адрес в `config.js`.

## Самопроверки

Тесты живут в `tests/` и запускаются при **работающем** сервере.
Каждый печатает список проверок с пометкой `OK` или `СБОЙ` и сам
создаёт себе комнату, поэтому прогонять их можно подряд и повторно.

| Тест | Что покрывает |
|---|---|
| `test.js` | этапы партии, права ведущего, все четыре режима, рисование |
| `roomtest.js` | изоляция комнат: чужие отрезки и команды не проходят |
| `mirrortest.js` | зеркало: ось, лимит, поведение при удержании |
| `uitest.js` | интерфейс целиком в эмуляторе браузера |
| `itchtest.js` | клиент на чужом домене: комната, вход по коду, раунд |
| `bootest.js` | первый экран: нет мелькания, кнопки объясняют себя |
| `timetest.js` | выбор длительности раунда и права ведущего |
| `guidetest.js` | «Проводник»: слово у одного, подсказки про право голоса |
| `infinitetest.js` | режим без ограничения: `secs=null`, ручная остановка |

`uitest.js` требует `npm install jsdom eventsource`. Он открывает две
«вкладки», проходит партию кликами и проверяет то, что видно глазами.
Стоит запускать после любой правки `index.html`: серверные тесты
клиентскую часть не покрывают — на этом уже один раз попался экран
лобби, который просто не отрисовывался.

## Что стоит сделать дальше

**Сначала — сыграть.** Проект технически опережает проверку: четыре
режима, шесть составов, комнаты — а полноценного теста на компании
из четырёх-шести человек ещё не было. Три вопроса, на которые нужен
ответ, прежде чем добавлять что-то ещё:

1. Разговаривают ли игроки друг с другом, или молча жмут кнопки.
2. Не убило ли зеркало кривизну — картинки стали аккуратнее, но игра
   называется «Криворучка», и нелепое расходится лучше красивого.
3. Возникает ли спор после разоблачения крота сам, без подсказки
   интерфейса.

**Голосование и очки** имеют смысл только если третий пункт
подтвердится. Иначе обсуждение съест вечер и ничего не даст.

**Известные ограничения.** Состояние живёт в памяти процесса: перезапуск
сервера обнуляет все комнаты. Партия не сохраняется, счёта нет.
На бесплатных хостингах сервис засыпает после простоя, и первый заход
после паузы занимает около полуминуты.
